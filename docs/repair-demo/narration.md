# One-minute narration

Read at about 150 words per minute. The video is silent so you can record your own voice.

> I wanted to test whether AI could improve how it works, then reuse that improvement on new problems.
>
> I gave Astra damaged Factorio factories and asked it to build and revise a Method: an executable procedure with code and agent steps.
>
> It practiced on ten factories. Then I froze the best version and compared it with fresh Astra runs on twenty unseen factories.
>
> The first version used three agent stages. That was slow. The better version used code to make a compact factory map, then one Astra session to diagnose, repair, and check.
>
> Median full time fell from ninety-three to seventy-one seconds on matched successful runs. Input tokens fell fifty-six percent.
>
> Both repaired every factory. The Method also avoided two tool-rule failures.
>
> The lesson: improve the procedure, then reuse it. Next I’ll test harder tasks and isolate which changes caused the gain.

## Shorter alternative

If your delivery needs more time, omit: “an executable procedure with code and agent steps” and “on matched successful runs.” Keep the matched-case qualification on the result card.

## Answer if asked whether it is more reliable

“In this sample it made fewer tool-rule errors: zero instead of two. Both repaired all twenty factories. Twenty cases are too few to establish a general reliability gain.”

## Footage label

“Native Factorio action replay • edited timing • no new model calls.”

These clips show the recorded world-changing requests applied to copies of the original damaged saves. They are not screen recordings of the timed trials. Observations and model thinking are omitted. Game speed, action spacing, and camera views are changed for the demo. The original action outcomes and final equipment are checked against the retained run. Benchmark numbers come only from the original trials.
